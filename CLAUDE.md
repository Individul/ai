# Cataloage

Hub de cataloage de legislație pentru colegi (ai.dumitru.cloud). Astro `output: 'server'` pe Cloudflare Workers, D1 pentru date, R2 pentru fișiere, Cloudflare Access pentru autentificare. Chatul cu citări merge pe textul extras din PDF-uri, cu modelul ales în Admin: **Claude Sonnet 5.5** (implicit, din creditele API lunare ale abonamentului Max) sau DeepSeek V4.1 Flash (rezerva). **Din 22 oct. 2026 Gemini File Search, Z.AI (GLM) și Claude-urile vechi (Haiku 4.5, Sonnet 5, Opus 5) sunt scoase din cod** (decizia lui Dumitru); coloanele lor din D1 (`surse.indexare`, `doc_google`, `operatie_google`, `indexare_mesaj`, `cataloage.magazin`, `credite`) au rămas, nefolosite, iar documentele indexate la Google n-au fost șterse acolo. Gemini Notebook (fostul NotebookLM) nu se integrează (fără API pe cont personal, fără încadrare); chatul e propriu, peste PDF-urile din R2. Din 10 sept. 2026 culegerea poate avea din nou un link spre caietul lui Dumitru (`url_notebook`, câmp în Admin, acțiune în antetul paginii): colegii sunt viewer acolo, pot întreba și pot folosi materialele Studio generate de el, nu pot genera; întrebările de acolo nu intră în jurnal (`docs/plans/2026-09-10-gemini-notebook-link.md`). Planurile: `docs/plans/2026-09-08-cataloage-v1.md` (hub), `docs/plans/2026-09-08-cataloage-v2-chat.md` (chat, consum, limite), `docs/plans/2026-09-08-cataloage-v3-zai.md` (motorul Z.AI, credite, buget; istoric).

## Convenții

- Totul în română: UI cu diacritice; comentarii, mesaje de commit și nume de fișiere fără diacritice; identificatori în română (`creeazaCatalog`, `verificaUpload`).
- **În interfață, catalogul se numește „culegere” (plural „culegeri”)**, cu acordurile la feminin („Culegerea nu există”, „Activă”, „Arhivată”); decizia lui Dumitru din 8 sept. 2026, pentru că „cataloage” sună greoi. În cod, în D1 (`cataloage`), în adrese (`/c/`, `/admin/cataloage/`) și în documentele tehnice rămâne „catalog”.
- Fără `owner`: datele sunt comune tuturor celor din Access. Scrierea e doar pentru admin, iar poarta e **în middleware** (`/admin*`, `/api/admin*`), nu în pagini. Paginile nu citesc `env.ACCESS_*` / `env.ADMIN_EMAILS` direct; identitatea vine din `Astro.locals.email` / `Astro.locals.admin`.
- Fișierele nu trec niciodată prin `arrayBuffer()` sau `formData()`: upload = `request.body` streamat în `FISIERE.put`, descărcare = `obj.body` în `Response`. Workerul are 128 MB.
- Obiectul din R2 se scrie înaintea rândului din D1 (audio) și se șterge înaintea rândului (surse, audio); un rând fără fișier nu trebuie să existe.
- Catalogul se arhivează (`stare = 'arhivat'`), nu se șterge; `ON DELETE RESTRICT` e plasa de siguranță.
- Formularele de admin sunt clasice (POST → `/admin/actiuni/*` → 303 cu `?ok=1` / `?eroare=`). Doar upload-ul are JavaScript (`src/scripts/incarcare.ts`).
- Doar trei modele în `TARIFE` (`validare.ts`): `claude-sonnet-5-5` (chat și corector), `claude-opus-5-5` (`doar_corector`) și `deepseek-flash`. Un model din setări care nu mai e în tabel (ex. un Gemini rămas în D1) se tratează ca necunoscut: chatul cade pe implicit (`SETARI_IMPLICITE.model`), corectorul pe `MODEL_CORECTOR_IMPLICIT`, iar `raspunde` aruncă 409. Jurnalul ține costul calculat la momentul cererii, deci rândurile vechi nu au nevoie de tarif.
- PDF-urile de la legis.md (mPDF) au 46 de octeți de gunoi înaintea `%PDF`: serverul îl taie la upload (`curataPdf`). Rescrierea cu pdf-lib din browser (`normalizeazaPdf`) era doar pentru indexarea Google și a plecat odată cu ea (22 oct. 2026), cu tot cu dependința.
- DeepSeek: numele din API pentru V4.1 Flash (10 sept. 2026) e `deepseek-flash`; `deepseek-v4-flash` și `deepseek-v4-pro` sunt retrase și redirecționate spre el. Tarifele DeepSeek din tabel sunt cele de la orele libere; la orele de vârf (01–04 și 06–10 UTC, luni–vineri) prețul e dublu: `factorTarif` în `validare.ts`, aplicat în `costMicrodolari`. În pagini se anunță **doar vârful** (`textVarf`): ora liberă e starea obișnuită, deci nu se mai scrie nicăieri (16 sept. 2026).
- **Încălzirea cache-ului DeepSeek**: `wrangler.jsonc` are `main: src/worker.ts` (Astro pentru HTTP + `scheduled`) și cron `0 5 * * 1-5` (05:00 UTC, înainte de orele de vârf). `src/lib/incalzire.ts` trimite, pentru fiecare culegere din `setari.incalzire` (casete în Admin, vizibile doar când motorul activ e DeepSeek), o întrebare minimă cu tot contextul, ca prefixul să intre în cache; se scrie în jurnal pe `sistem@incalzire`. Sare când motorul nu e DeepSeek sau lipsește cheia. Nu se poate simula local: adaptorul Astro scoate `no_bundle`, iar `--test-scheduled` nu injectează ruta `/__scheduled`; verificarea s-a făcut în producție cu un cron temporar `*/2 * * * *` (13 sept. 2026).
- `src/lib/deepseek.ts` (fostul `zai.ts`) e clientul OpenAI-compatibil al lui DeepSeek (`BAZA_DEEPSEEK`, `DEEPSEEK_API_KEY`; cache automat pe prefix, tokenii din cache în `usage.prompt_cache_hit_tokens`, plătiți la `TARIFE[model].intrare_cache`). Tot acolo stau promptul chatului (`PROMPT_SISTEM_CHAT`, folosit și de Claude), `Schimb`, `CerereChat`, `RaspunsModel` și `EroareModel` (eroarea comună a motoarelor cu text). Alegerea motorului și orchestrarea întrebării sunt în `src/lib/motor.ts` (`raspunde`, `cheieMotor`, `disponibilePentruChat`); rutele și paginile nu apelează clienții direct. Modelul din `setari.model` decide motorul (`TARIFE[model].motor`: claude | deepseek). **Gândirea rămâne pornită la DeepSeek**, fiindcă 4.1 raționează în mai mulți pași și fără ea refuză întrebările care leagă două-trei articole (12 sept. 2026); `max_tokens` e 8192, tokenii de gândire intrând în plafon. Planul: `docs/plans/2026-09-09-deepseek.md`.
- **Corectorul de documente Word** (`/corector`, 14 sept. 2026; plan `docs/plans/2026-09-14-corector.md`):
  - **Fișierul nu pleacă din browser.** `src/lib/docx.ts` (fără DOM, ca să ruleze în workerd la teste: tokenizer + arbore minim) scoate paragrafele și pune corecturile înapoi ca revizii Word: `w:del` / `w:ins`, cu `rPr`-ul run-ului original, `w:id` după cel mai mare existent. Se rescriu doar run-urile atinse.
  - **Modelul nu rescrie textul.** Modelul din `setari.model_corector` (select separat în Admin) întoarce `{i, vechi, nou, tip, motiv}`. „vechi” se caută în paragraf cu echivalențe caracter la caracter (ş/ţ cu sedilă = ș/ț, ghilimele, spațiu fix). Diferența pe cuvinte (LCS) dă reviziile minime.
  - **Spațiile nu se corectează și nu se raportează** (16 sept. 2026, decizia lui Dumitru): o corectură care schimbă doar spațiile („or.Soroca” → „or. Soroca”, „эл.адрес” → „эл. адрес”, spațiile duble) nu intră nici în document, nici în listă, fiindcă îneacă greșelile adevărate. Promptul nu le mai cere, iar `doarSpatii` din `corector.ts` le aruncă la citirea răspunsului, în ambele moduri; o observație a cărei rezolvare e doar un spațiu se aruncă la fel. Spațiul dintre două litere („desine” → „de sine”) și semnele puse sau scoase („№.6” → „№ 6”) rămân corecturi adevărate.
  - **Ce nu se corectează automat:** textul din câmpuri, din revizii existente, din casete de text și cel care trece peste tab sau rând nou. Corectura rămâne „de verificat”.
  - **Două moduri, și în hub (15 sept. 2026):** `corectura` (implicit) trimite doar corpul, pe loturi, în paralel; `verificare` trimite tot documentul (corp, antete, subsoluri, note) într-o singură cerere la `/api/corector/{id}/verificare` și întoarce, pe lângă corecturi, `observatii` — date care se contrazic între paragrafe aflate în locuri diferite, rubrici goale, formatare ruptă, îndoieli juridice. Aceleași funcții ca în aplicația de Mac (`analizeazaIntreg` / `paragrafeIntreg` / `aplicaCorecturiIntreg`, `cerereVerificare` / `verificaDocument`), deci corecturile intră și în antet. Plafon `LIMITA_VERIFICARE` (**100.000 de caractere** de la 22 sept. 2026, la cererea lui Dumitru; era 40.000); peste el, pagina cere modul corectură. Ieșirea are `maxTokens` 64.000 (gândirea intră în plafon; DeepSeek verificat pe viu că acceptă), iar un răspuns tăiat la jumătate se spune pe nume, nu mai apare ca „nici corecturi, nici observații”. Verificat pe viu pe un act de 98.376 de caractere: 45.337 de jetoane de intrare, 16.425 de ieșire, 67 s, 29 de bani pe DeepSeek. O singură cerere pe corectare (a doua dă 429), iar fiecare rută refuză corectările din celălalt mod. Jurnalul ține `mod` și `observatii` (migrația `0006_corector_verificare.sql`).
  - **Observațiile vin cu soluție (16 sept. 2026, cerința lui Dumitru):** fiecare observație are `solutie` (ce trebuie făcut, concret) și, când rezolvarea se vede din document (exponent pierdut, denumire scrisă altfel decât în restul actului, trimitere scrisă în două feluri), și `corectura` `{i, vechi, nou}`, validată cu aceleași reguli ca o corectură obișnuită. În hub, sub fiecare soluție aplicabilă sunt două butoane: **«Acceptă soluția» / «Lasă cum e»**, implicit lăsată. La fiecare alegere documentul se reface întreg (`aplicaCuMentiune` cu corecturile modelului plus soluțiile acceptate), deci fișierul de la descărcare e mereu ce vezi în pagină, iar corectura acceptată apare și în listă. Unde rezolvarea cere date din afara documentului (numărul de înregistrare, care dintre două numere de telefon e cel bun), modelul nu ghicește: scrie doar ce are omul de completat, iar în pagină apare „Nu se poate pune automat”. **Și în aplicația de Mac** (16 sept. 2026): aceleași două butoane sub fiecare observație. Fiindcă acolo documentul e deja scris pe disc, motorul are un mod nou, `--reaplica`: primește pe stdin planul (`{fisier, iesire, motor, model, corecturi}` — corecturile modelului, cu numărul paragrafului, din câmpul `plan` al rezultatului, plus soluțiile acceptate) și scrie documentul din nou peste același fișier, pornind mereu de la originalul neatins, fără nicio cerere la model. `Motor.reaplica` din aplicație îl pornește la fiecare alegere; bifele observațiilor care se completează de mână nu ating documentul.
  - **Datele personale se maschează înainte de plecare (16 sept. 2026, cerința lui Dumitru):** `src/lib/mascare.ts` (fără rețea, fără DOM: browser, node și workerd) găsește numele de persoană, IDNP-ul, telefonul, e-mailul, IBAN-ul, seria actului, numărul auto, adresa de stradă și data nașterii, le înlocuiește cu date false dar **plauzibile** (`src/lib/nume-md.ts`: prenume, cuvinte care nu sunt nume, rezervorul de nume false), iar corecturile și observațiile se desfac înapoi înainte de a intra în document. Promptul nu se schimbă: textul îi pare modelului firesc. Trei niveluri, ținute minte ca modul de lucru: `tot` (implicit), `identificatori`, `fara` — în hub al treilea grup de butoane, în aplicație rândul „Date”, în comandă `--mascare` (plus `--arata-ce-pleaca`, care scrie în directorul temporar exact textul trimis). Harta stă în browser, respectiv în procesul node, și nu se scrie nicăieri; numele fișierului se maschează și el, altfel ajungea întreg în `corectari.fisier`. **Trei paznici** opresc un nume inventat să ajungă în actul real: corectura care atinge o zonă mascată se aruncă, cea în care a rămas o urmă din rezervor (și flexionată) se aruncă, iar înainte de scriere textul de inserat se scanează încă o dată — dacă a scăpat ceva, documentul nu se scrie. **Capcane:** rădăcina cuvântului se ia pe `\p{L}`, nu pe `a-z`, altfel orice cuvânt rusesc primea rădăcină goală și se potrivea cu oricare altul (tot antetul rusesc ajunsese mascat); antetul rusesc se maschează doar după un declanșator rusesc; „al/ale” nu e declanșator („Șef al Direcției”). **Ce mascarea i-ar lua modelului se face în cod** (`verificaDate`, pe datele adevărate): același om scris în două feluri, IDNP-uri aproape la fel, telefon scurtat, dată imposibilă și contactele care diferă între varianta română și cea rusă de pe același rând. Observațiile astea apar și în modul corectură. **Sunt grupate și plafonate** (`LIMITA_PE_VERIFICARE = 5`): fără asta, un act de 98.000 de caractere cu zeci de numere asemănătoare scotea 2.451 de observații, câte una pe fiecare pereche (22 sept. 2026). Nu e anonimizare, și se spune în ambele interfețe: harta există, restul actului pleacă așa cum e, un nume rar poate scăpa, iar partea rusă nu e acoperită.
  - **Gândirea e pornită la DeepSeek.** Fără ea, pe 14 sept. 2026, a scăpat jumătate din greșeli și a stricat cuvinte corecte. De aceea: loturi de 4.000 de caractere, 4 în paralel, `max_tokens` 32.768.

A doua trecere pornise și cu **19 unelte**: `--tools ""` scoate doar uneltele din setul de bază, serverele MCP din setările utilizatorului își aduc uneltele lor — de aceea se trimite și `--strict-mcp-config` (nu `--bare`, care ar forța autentificarea pe cheie de API și ar rupe planul personal). ## Development

Prima dată: `cp .dev.vars.example .dev.vars` (completează `ANTHROPIC_API_KEY` și/sau `DEEPSEEK_API_KEY`) și `npm run migrate:local`. În producție cheile sunt secrete pe Worker (se pot pune și din panoul Cloudflare: Workers & Pages → ai → Settings → Variables and Secrets; cheia Anthropic trebuie să fie legată de un workspace, altfel API-ul cere antetul `anthropic-workspace-id`). **Capcană (Windows, 8 sept. 2026):** la promptul interactiv al `wrangler secret put`, Ctrl+V a fost înregistrat ca un singur caracter de control (cod 22), nu ca lipire; orice cerere cu acel antet `Authorization` pica pe loc cu „Network connection lost”. Secretele se pun prin stdin, din `.dev.vars`: `(Get-Content .dev.vars | Where-Object { $_ -like 'DEEPSEEK_API_KEY=*' }) -replace '^DEEPSEEK_API_KEY=','' | npx wrangler secret put DEEPSEEK_API_KEY`. **Deploy de pe Windows (22 oct. 2026):** `npx wrangler login` (OAuth cu drept de scriere; logarea veche avea doar citire și dădea 7403), apoi `npm run deploy`. Oprește întâi orice `npm run dev:worker`: procesele `workerd` rămase țin `dist` blocat și build-ul pică cu EPERM.

Pentru verificări vizuale folosește `npm run dev:worker` (port 8787), care servește build-ul real. `astro dev` cu adaptorul Cloudflare servește uneori paginile fără stiluri (rulează în workerd și pierde mediul de dev la pornire rece); rutele, middleware-ul și API-ul merg corect.

Capcana: `wrangler dev` își face lista de assets o singură dată, la pornire, din `dist`. Dacă rulezi `npm run build` cât timp serverul merge, răspunde 404 la CSS și JavaScript. Repornește `npm run dev:worker`. Prima cerere cu corp după pornire poate pica cu „Network connection lost” în proxy-ul local; a doua merge.

Teste: `npm test`. Tipuri: `npm run check`. Deploy: `npm run deploy` (tokenul Cloudflare e în `CLOUDFLARE_API_TOKEN`, din `~/.zshrc`). **Capcană (15 sept. 2026):** shell-ul uneltei Bash din Claude Code nu încarcă `~/.zshrc`, deci wrangler cade pe o autentificare OAuth veche și `wrangler d1 migrations apply ai --remote` răspunde 7403 („account is not valid or is not authorized”). Comenzile spre Cloudflare se rulează prin `zsh -ic '…'`, care încarcă `~/.zshrc`; `npx wrangler whoami` arată „User API Token … read from the CLOUDFLARE_API_TOKEN environment variable” când e bine. Ordinea la o migrație nouă: întâi `npm run migrate:remote`, apoi `npm run deploy`.
